- **Noto legacy duplicate** `assets/original/Fonts/Noto Sans Osmanya.ttf` has the same SHA-256 as `assets/NotoSansOsmanya.ttf` and is retained because `app/original.kv` still names that historical relative path. ## Transitive Material Design Icons font

Saylacian source does **not** vendor the Material Design Icons TTF. It depends on `KivyMD==1.2.0`, pinned in `requirements-runtime-lock.txt`. The immutable [KivyMD 1.2.0 PyPI release metadata](https://pypi.org/project/KivyMD/1.2.0/) identifies the Iconic font as by the Material Design Icons community and declares SIL Open Font License 1.1. The installed wheel's font name table says “Version 1.0” and “Generated by svg2ttf from Fontello project”; KivyMD does not pin an upstream icon-font commit. For this source repository, the binary arrives only with the declared third-party dependency and its upstream notice resolves the dependency's stated licence. The PyInstaller recipe collects KivyMD assets, so any Windows binary distribution must include OFL attribution and verify its exact packaged font. The current MDI OFL text is retained at `notices/SIL-OFL-1.1-Material-Design-Icons.txt`.

## Old Nubian reading references

- The 29 character readings in the Old Nubian reader are based on Table 1 in Vincent W. J. van Gerven Oei, “[Old Nubian](https://escholarship.org/uc/item/03x6d68h),” *UCLA Encyclopedia of Egyptology* 1(1), published 2024-06-14, DOI [10.5070/G9.3919](https://doi.org/10.5070/G9.3919). The article is licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Saylacian transcribes the table's character/readings and adds code-point lookup, Unicode case handling, warnings and reverse segmentation. Attribution: “Based on Table 1 in van Gerven Oei, ‘Old Nubian’ (2024), UCLA Encyclopedia of Egyptology, CC BY 4.0.” These are limited character readings, not an independently reviewed Old Nubian transliteration system.
- **Smagina, *The Old Nubian Language*, translated by José Andrés Alonso de la Fuente** (Punctum Books / Dotawo, 2017) is licensed CC BY-NC-SA 4.0, as stated on the [publisher/JSTOR book page](https://www.jstor.org/stable/jj.2354037). Saylacian does not bundle that book's text, transliteration or glossary.
- The DBMNT table remains a useful bibliography item, but it is no longer the source of bundled Old Nubian readings. Its PDF is not bundled; download availability alone is not a reuse grant.

## Python dependencies

`requirements-runtime-lock.txt` pins the Kivy app/runtime dependency set; `requirements-website.txt` contains optional Flask. CI/dev tools are in `requirements-dev.txt`. The optional `requirements-afrislm.txt` pins llama-cpp-python 0.3.36 (MIT) from its upstream CPU-wheel index; it is separate from the base lock and only needed for the separately downloaded AfriSLM pack. Dependencies are installed from their upstream package repositories and are not copied into this source tree. Their upstream package notices apply. Checked package metadata lists include MIT (Kivy, KivyMD, Kivy-Garden, CTranslate2, charset-normalizer, filetype, PyYAML, llama-cpp-python); Apache-2.0 (`notices/Apache-2.0.txt`, shared by Requests, SentencePiece, and the pinned OPUS-MT pack); BSD-family / public-domain alternatives (NumPy, py3langid, Pygments, Docutils, idna); MPL-2.0 (certifi); HPND (Pillow); PSF (pywin32); MIT (kivy-deps.angle / glew); and zlib (kivy-deps.sdl2). Some transitive packages publish multiple licences or incomplete PyPI metadata; inspect the exact pinned distribution before redistributing a built binary. Kivy declares `pypiwin32` as a Windows-only transitive dependency. Its PyPI 223 distribution is a metadata-only wrapper with no importable files or licence file and reports `UNKNOWN`; the application separately pins `pywin32` (PSF). Neither package source nor DLLs are vendored here. Their presence must be rechecked in any binary bundle.

The source repository contains no Windows DLLs or installer binaries. Native DLL notices are therefore a separate Windows binary-release check, not a source-repository blocker. See `docs/PACKAGING.md` before building or distributing a binary.
