# Security policy

Saylacian is under active development. Do not send credentials, private translation content, or vulnerability details through public issues.

GitHub private vulnerability reporting has not been verified for this repository. Do not include sensitive details in a public issue. A repository owner should enable private vulnerability reporting and confirm maintainer notifications before treating it as a monitored channel. If GitHub's private report option is unavailable, there is no verified private reporting channel. See GitHub's [private vulnerability reporting setup](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).

After enabling private reports, subscribe the responsible maintainer to the repository's **Security alerts** notifications (or all activity), then verify delivery in GitHub notification settings. Email delivery depends on the user's notification preferences; configure it only with the account owner's approval. GitHub's [notification setup instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository#configuring-notifications-for-private-vulnerability-reporting) describe those steps.

The project does not promise a response time or security support for old versions. Please include the affected version, platform, and a minimal reproduction in a private report, and omit personal translation data.
